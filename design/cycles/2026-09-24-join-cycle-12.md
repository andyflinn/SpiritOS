## MEASURED AT `5cd0b12`

Every premise this cycle rests on, checked against the tree rather than
remembered. Quoted text with `path:line`, per `FORMAT.md` and rule 13.

- **`join/` does not exist.** No directory, no route, no suite.
- **The owner mints with a verb that already exists.** A signed owner
  request carrying `body.invite`: *"MINTING AN INVITE, asked for the same
  way. The owner's name is not taken from the packet: it is read from
  allow.json here"* (`spirit/run/js/relay.js:3677-3684`).
- **Seats are already counted at mint time and never cached.** *"COUNTED
  AT MINT TIME, NEVER CACHED. A relay restarted with a lower ramLimitMB
  would otherwise keep minting against the figure it had when it came
  up"* (`relay.js:1997-2001`), refusing with 507 and the sentence *"this
  relay is full: … Minting now would promise a seat that does not exist"*
  (`relay.js:2008-2014`). **So this is NOT cycle-12 work.** The alpha
  plan listed it as a decision; the tree already holds it.
- **An expired invite returns its seat** (`relay.js:2004-2006`), which is
  why shortening expiry is a tightening lever and not a new mechanism.
- **The proxy is gated by the owner's list, read on every call.** *"The
  owner's list (relay-state/proxy.json, proxyList.js) is read on every
  call, so a close takes effect on the next one"*
  (`spirit/run/js/server.js:490-492`); the list is `proxyList.js`, with
  `allow()` and `remove()` at `:128` and `:139`.
- **The keys come from that list, not from code** —
  *"THE KEYS come from that list, not from code (envSecrets.js applies
  it)"* (`server.js:494`).
- **The claim route is unchanged by this cycle**: `POST
  /api/relay/claim` (`spirit/run/js/relayServer.js:585`, `:799`).

**Consequence, and it is the finding of the measurement:** the relay
needs no change in this cycle. Every relay-side mechanism `join` depends
on is built, gated and asserted already. What is missing is entirely on
the node side and in a new directory.

## REQUIREMENTS

### R1 — `join/` is a directory in this repository, and it is publishable

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

The site, its node client and the minting program all live in `join/` and
all reach the remote. Nothing in it is a secret: `relay-state/` is
gitignored, so the client id, the secret and the owner key are on Andy's
box and never in the tree.

**Asserted by:** the directory exists; no file under `join/` contains a
credential-shaped literal; `.gitignore` does not exclude it.

### R2 — the site runs its own node, an ordinary member

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

No privileged status, no second protocol. The site's node is a member of
spirit like any other, and its only power is that Andy's node answers it.

**Asserted by:** the site's node configuration names no owner key and no
relay-side privilege; it reaches its own loopback door and nothing else.

### R3 — a visitor signs in with GitHub, and that is the only identity

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

GitHub only — Andy: *"our repo lives there, and github is in the loop
already."* No email, no mail sender, no address kept or deleted.

**Asserted by:** the flow has one identity provider; no field collects an
address.

### R4 — the site receives the one-use code and does not exchange it

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

**The security claim of the whole design.** The site holds a code it
cannot spend: the exchange needs the client secret, which is on Andy's
box. A compromised site can deny service or waste quota but cannot invent
accounts, because a code issued for another `client_id` fails.

**Asserted by:** no exchange request in `join/`; the code leaves only as a
`peer.post` payload. **See divergence prediction 3** — whether this can
be asserted positively rather than by absence is an open question this
cycle must answer, not assume.

### R5 — the code travels to Andy's node as a signed, sealed post

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

It is an ordinary `peer.post`: sealed to his node's cipher key, signed by
the site's identity key. **Authenticated by signature** — no API key, no
bearer token, nothing to leak.

**Asserted by:** the post is sealed and signed; the relay carries
ciphertext; a post from an unknown key is not acted on.

### R6 — Andy's node exchanges the code, applies the policy, and mints

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

Through `net.fetch` under the proxy gate (`server.js:490`): POST
`github.com/login/oauth/access_token`, then GET `api.github.com/user`.
Then the seat policy, then the existing owner verb
(`relay.js:3682-3684`). The invite is posted back.

**Asserted by:** the minting program calls `net.fetch` and the owner
verb, and nothing else; the same `redirect_uri` and `client_id` are
carried to the exchange.

### R7 — asleep means refuse, and the refusal is a sentence the visitor can act on

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

Never queue: the code dies in ten minutes and queueing means storing it.
**See divergence prediction 1.**

**Asserted by:** with Andy's node unreachable, the visitor gets a refusal
naming what to do; nothing durable holds the code afterwards.

### R8 — closing the proxy gate turns onboarding off, with one owner verb

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

The off switch must be true on the day it matters, so it is exercised
rather than documented. The gate ships **closed** and is opened
deliberately.

**Asserted by:** with the host removed from `proxy.json`, the mint path
refuses; `proxyList.remove()` is the only action needed.

### R9 — a full relay is visible to the visitor, not only to the owner

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

The relay already refuses the mint with 507 and a full sentence
(`relay.js:2008`). `join` must turn that into something a stranger can
act on, which per the alpha plan is the **"run your own relay"** door.
**See divergence prediction 2.**

**Asserted by:** a mint refused for capacity produces a visitor-facing
page that offers the other door and does not show the relay's internal
figures.

### R10 — the claim screen collapses from three fields to one

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

`natterDetails.js:590` asks public label, token and invite name because a
human minted it and said a word out of band. A self-minted invite already
knows the name, so only the token is carried and the display name
defaults to the GitHub login. **`/api/relay/claim` is unchanged** — screen
copy and defaults, not a route.

**Asserted by:** the claim screen takes one field; `relayServer.js:799`
is untouched.

### R11 — the record links a GitHub account to a node key, and says so

**Status:** OPEN. Nothing built; `join/` does not exist at `5cd0b12`.

*"Nothing kept"* is not true: a delivered post is logged with its payload
and the log is permanent. An expired invite and a spent one-use code are
worthless — **accepted by Andy** — but the link between a GitHub account
and a node key is real and is stated plainly on the page.

**Asserted by:** the page carries that sentence; nothing else about a
visitor is written anywhere durable.
