# ZS4 Node Architecture Principles

**Version:** 0.1 (16 May 2026)  
**Author:** Andy Flinn

## Foundational Principle: Single-User Personal Node

Every **Personal Node** in the ZS4 network is designed for **exactly one human being** — its owner.

It is **not** a multi-user system. It is **not** a shared server.

### Why This Matters

- The Personal Node **is** the digital extension of one person’s spirit.
- All interfaces, data structures, and logic are built around a single identity.
- This eliminates massive complexity and keeps the system honest.

### Implications

- No users table, no multi-account support, no RBAC inside the node.
- Sharing and collaboration happen exclusively via **peer-to-peer** object exchange with explicit consent.
- Other people never log into your node — they connect as peers.

### Philosophical Statement

> A ZS4 Personal Node is not a server that hosts data about a person.  
> It **is** the digital embodiment of that person.

This single-user design is a deliberate declaration of sovereignty.
